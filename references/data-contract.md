# Wind MCP 取数契约

所有取数都走 `mcp__wind-*` 系列。本文件说明每个字段从哪来、单位是什么、以及踩过的坑。

---

## 1. 成交额（turnover，单位：元）

```
mcp__wind-fund-data__get_fund_kline
  windcode   = "510300.SH"
  begin_date = "2026-11-06"
  end_date   = "2026-11-06"
  period     = "10"        # 10 = 日线
```

取每根 K 线的 **`amount`**（成交额，元），**不是 `volume`**（成交量，份）。
返回可能是数组，也可能是一段文字描述，两种都要能解析出 `日期 → amount` 的映射。

> 校验：单只宽基 ETF 日成交额通常在 1e8 ~ 5e10 元之间。若拿到 1e5 量级，那是万元；
> `store.merge_inbox` 会自动 ×1e4 并打警告。

---

## 2. 净申购额（flow，单位：亿元）

```
mcp__wind-fund-data__get_fund_performance
  question = "查询沪深300ETF华泰柏瑞(510300.SH)最近1个月每个交易日的基金资金净流入额"
```

这是**自然语言接口**，返回每个交易日的「基金资金净流入额」。它是份额变动 × 净值的实测值，
不是估算，这是整个模型里唯一「硬」的输入。

### 三个必须注意的点

1. **一次只能查一只**。传多只会静默截断，只返回前 5 只不到——不会报错，最坑。
   正确做法是循环 12 次，每次一只。
2. **返回含 .SH 与 .OF 两份**。联接基金（.OF）那份要丢掉，只留场内代码。
3. **单位不统一**。同样一句问法，不同代码可能返回亿元、百万元或万元。
   `apply` 的单位自检（`|flow|×1e8 ≤ 3×turnover`）就是为了兜这个底。
   命中警告时不要改数据硬塞，回去看原始返回的标题里写的单位。

### 当日盘中返回 null

收盘前查当天，`flow` 是 `null`。所以：

- **盘中判定只能用成交额**（见 `apply-intraday`）
- **收盘后再抓当天 `flow`**，否则库里会缺一天，`common_dates` 会把整段窗口往前退一天

---

## 3. 基准（沪深300 收盘）

```
mcp__wind-index-data__get_index_kline
  windcode   = "000300.SH"
  begin_date / end_date / period = "10"
```

取 `close`。模型用它的日涨跌幅来判定波段、算与买入的相关性。

---

## 4. 规模（shares × price，单位：亿元）

```
mcp__wind-fund-data__get_fund_price_indicators
  windcode = "510300.SH,510310.SH,..."
  indexes  = "中文简称,最新交易日,最新成交价,流通份额,最新净值,涨跌幅"
```

**每月更新一次即可**（规模只用于展示，不参与归因计算）。

⚠️ 这个接口返回的「基金规模」字段与「流通份额 × 最新价」**差 0.5–0.6 倍**，口径不一致。
统一用后者，写回 `data/universe.json` 的 `shares` 与 `price`，`scale` 由脚本算。

## 5. 调用预算

| 场景 | 调用数 |
|---|---|
| 首次建库（30 个交易日） | 12 K线 + 12 净流入 + 1 指数 ≈ 25 次 |
| **日常增量（1 天）** | 同上 25 次（每只仍要单独查，无法批量） |
| 只更新规模 | 1 次 |

> QPS 约 2 次/秒。串行发，别并发。25 次大约 15 秒。

---

## 6. 建库前的自检清单

跑 `python scripts/update.py status` 后应看到：

- 12 只标的的「成交额天」与「净申购天」**相等**
- 全池齐备的交易日 ≥ 21 天
- 基准收盘天数 = 交易日数

任何一项不对，先别跑 `compute`——`common_dates()` 会取所有标的同时有成交额和净申购的交集，
缺一只就会把窗口整体缩短，模型结果会变形。
